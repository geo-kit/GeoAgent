# GeoAgent

Ассистент, встроенный в [GeoView](https://github.com/geo-kit/GeoView) — приложение для
просмотра моделей месторождений. Он отвечает на вопросы об открытой модели и управляет
приложением на естественном языке: находит деку, открывает её, запускает расчёт,
заполняет форму оптимизации.

GeoAgent ничего не считает сам. Он управляет GeoView, а тот выполняет работу и
показывает результат в своих вкладках. Благодаря этому агент остаётся небольшим: семь
зависимостей, без Julia и без солвера.

## Что он умеет

| Инструмент | Что происходит |
|---|---|
| `find_reservoir_models` | Перечисляет подкаталоги и файлы `.DATA` / `.hdf5` в одном каталоге. Содержимое файлов не читает никогда. |
| `load_model_in_geoview` | Открывает модель в GeoView. |
| `run_simulation_in_geoview` | Запускает расчёт JutulDarcy для уже открытой модели средствами GeoView. Не принимает аргументов, поэтому не может подменить деку, отличную от той, что на экране. |
| `prepare_optimization_in_geoview` | Заполняет форму оптимизации по забойному давлению и открывает вкладку. Расчёт не запускает — кнопку Optimize нажимаете вы. |

Вопросы о загруженной модели не требуют ни одного инструмента: GeoView в начало каждого
сообщения добавляет сводку того, что на экране (путь, сетка, активные ячейки, фазы,
скважины, даты, есть ли результаты расчёта).

Инструменту оптимизации нужны все двенадцать экономических и инженерных параметров. Это
сделано намеренно: без них агент физически не может его вызвать, поэтому вместо того
чтобы выдумать цену нефти и уверенно выдать бессмысленный NPV, он спрашивает.

## Чего он намеренно не умеет

Никаких команд оболочки. Никакого исполнения кода. Не редактирует и не удаляет файлы. Не
читает содержимое файлов. Не обращается к сети, кроме провайдера модели. Единственное,
что он записывает, — JSON-запрос в собственный каталог артефактов GeoView.

Переменная `GEOAGENT_MODEL_ROOTS` ограничивает каталоги, в которых он может искать и
открывать модели. Если она не задана, он может открыть любой доступный на чтение файл
модели — ровно то же, что доступно через поле ввода пути в самом GeoView.

## Установка

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/). Репозиторий разворачивается рядом
с GeoView:

```
your-workspace/
├── GeoView/
└── GeoAgent/
```

```bash
uv venv && uv pip install -e . --group dev
```

Затем скопируйте `.env.example` в `.env` и впишите ключ API того провайдера, которым
пользуетесь.

## Запуск

Обычно запускать его отдельно не нужно: это делает GeoView и направляет на него свой чат.

```bash
python -m geoview.app --server --port 8080 --agent --agent-provider openai --agent-model gpt-5-mini
```

Отдельно — для разработки через LangGraph Studio:

```bash
langgraph dev --host 127.0.0.1 --port 2024 --no-browser
```

Перед этим задайте в `GEOVIEW_RESULT_DIR` путь к каталогу `.agent_runtime` внутри
GeoView, иначе инструментам будет некуда доставлять свои запросы, о чём они и сообщат.

## Настройка

Всё задаётся переменными окружения, см. `.env.example`.

| Переменная | Назначение |
|---|---|
| `GEOAGENT_MODEL` | `провайдер:модель`. Провайдеры: `openai`, `lmstudio`, `ollama`. GeoView выставляет её из своих ключей запуска. |
| `OPENAI_API_KEY`, `OPENAI_BASE_URL` | OpenAI или любая совместимая с ним точка доступа. |
| `LMSTUDIO_BASE_URL`, `LMSTUDIO_API_KEY`, `LMSTUDIO_MODEL` | Локальный сервер LM Studio. |
| `OLLAMA_BASE_URL` | Ollama. |
| `GEOVIEW_RESULT_DIR` | Куда доставлять запросы. Выставляется GeoView. |
| `GEOAGENT_MODEL_ROOTS` | Необязательный список разрешённых каталогов, разделитель `os.pathsep`. |

## Как он общается с GeoView

Эти два процесса работают раздельно, поэтому обмениваются не через API, а через общий
каталог. Агент пишет манифест, а затем публикует указатель на него:

```
<GEOVIEW_RESULT_DIR>/results/<run_id>/result.json   # что сделать и с чем
<GEOVIEW_RESULT_DIR>/results/latest.json            # {"run_id": ...}, пишется последним
```

GeoView раз в секунду опрашивает указатель и разбирает манифест по полю `type`. Указатель
пишется последним, поэтому наблюдатель никогда не прочитает наполовину записанный запрос.
Новая возможность — это новый `type` с обеих сторон; транспорт при этом не меняется.

## GeoAgentPro

GeoAgent управляет приложением. GeoAgentPro рассуждает о разработке месторождений: пишет,
запускает, проверяет линтером и чинит код JutulDarcy на Julia, ищет по документации
JutulDarcy, выполняет собственные расчёты и многошаговые автономные сценарии, работает из
командной строки и как MCP-сервер, а не только внутри GeoView. Поставляется отдельно.
